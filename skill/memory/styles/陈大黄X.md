## 结构模板与开头

| 场景 | 可复用模板 | 边界 |
|---|---|---|
| 短帖 | 一个发现、问题或判断 → 必要信息 → 合适的停点 | 可用选择、问题或趣味观察结束，不凑行动清单 |
| 技术解释 | 熟悉场景 → 对应关系 → 技术概念 → 工程动作 | 类比不能证明技术事实 |
| 观点避坑 | 行为 → 后果 → 机制 → 选择标准 | 情绪不能代替理由 |
| 资源推荐 | 新发现或使用者需求 → 用途/接入/输出/成本 → 链接 | 可有兴奋感，不添加无依据亲测、生产稳定性 |
| 问题帖 | 限定情境 → 一个可回答的问题 | 不把每篇都写成互动诱导 |
| 可选对白 | 合理表象 → 追问成本 → 后果升级 → 矛盾回收 | 角色虚构、用户按需启用 |

开头先出现一个可以看见的对象、发现或具体判断；不机械复制“我很好奇一个问题”“发现一个大缝合怪”。朋友式称呼与第一人称判断可自然出现。X 默认无标题。需要标题时，用具体问题或任务，不沉淀来源不存在的爆款标题效果。

### 本轮保留与撤回

- 保留并增强：朋友式分享、具体用途与成本、清楚判断、自然口语与轻吐槽。第一人称可用于当前想法，经历须来自用户。
- 收缩：场景→机制→动作只作为解释类的一条路径，不作全部文章的骨架；结尾与题材匹配。
- 不作默认：连续感叹、粗口、对白、固定称呼、固定口头禅。两组中感叹号只在提炼组 2/10 条出现，检查组 0/10 条；另外的全体候选又有 74 条命中，说明该元素存在但应按场景启用。
- 撤回证据不足的推导：CSV 平均字数等于作者习惯长度、所有不以 @ 开头的记录都是原创、点赞高证明某种写法有效。
- 冲突处理：来源强调“不完美”时，只转为自然表达；错误事实、故意病句、不礼貌攻击与收益保证不迁移。全局人格保持原样。

后续修订触发：若用户指出输出仍太像说明书或语气过满，先对照具体原句调整对应模式。若要重估完整结构与结尾，应补完整新样本；本次不据截断文本重新设定文章长度。

## 标点、口语与冲突处理

来源以空行、句号和冒号组织解释；对白依赖角色标签和短答。强烈情绪集中在部分批评与讽刺题材，不能把它推广成所有文章的固定语气。

与基础人格可能冲突的粗口、人身攻击、虚构第一人称、极端概括不迁移。只保存高层表达规律；人格没有改变。互动的组织观察不替换全局互动规则。
